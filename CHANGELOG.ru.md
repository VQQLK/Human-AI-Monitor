### Изменено
- **docs/architecture.md §2.4**: расписание Cron Trigger обновлено с еженедельного (Monday 06:00) на 5 batches ежедневно
- **docs/architecture.md §3**: Data Flow обновлён для показа пути D1 → GitHub Actions → репозиторий с задержкой синхронизации
- **README.md**: описание Dual-sync workflow расширено с расписанием и задержкой видимости

### Added
- **Динамический cron-batching**: оффсеты/лимиты вычисляются в рантайме из `SOURCES.length` функцией `computeBatches()` (свойства проверены для всех N до ёмкости 44; N=41 по-прежнему даёт [8,8,8,8,9]); N > ёмкости громко отказывает через cron_drift_events — ручная сверка при изменении источников больше не нужна
- **Политики реестра закодированы**: docs/ — EN+RU по дизайну (аудит-чек docs-pairs); политика истории CHANGELOG (EN минималистичен, глубина RU/ZH совпадает) задокументирована в AGENTS.md правилах 3/10
- **Ясность терминологии**: сообщение проверки глоссария в repo_audit переформулировано — ZH-глоссарий содержит утверждённые переводы каноничных EN-фраз (канон — EN, RU/ZH — зеркала); в AGENTS.md правило 2 добавлено то же уточнение
- **Наблюдаемость дрейф-событий** (находка №2, вторая реализация): cron-гард дрейфа персистирует события в D1-таблицу `cron_drift_events`; новый эндпоинт `/drift-events` возвращает последние 100 — рантайм-гард наблюдаем, а не просто строка в логе
- **Самоотчёт /health и живой мониторинг**: `/health` теперь отдаёт version, sources_count, batches_planned, batches_ok; новый ежедневный workflow `live-monitor` сверяет живой API с git (паритет версий, покрытие батчей, персистенция переводов) — закрывает находку №2 ночного аудита
- **Честность coverage**: заявление о покрытии в README аннотировано (60% измерено по 7 юнит-тестируемым наборам, точка входа API исключена); добавлен скрипт `npm run coverage`
- **AGENTS.md**: руководства репозитория для ИИ-агентов — 10 жёстких правил, выведенных из консистентность-ревью 2026-09 (сгенерированный код, промпт как поведение, зеркалирование от EN-канона, версия из единого источника, cron-инварианты, жизненный цикл протоколов, взаимодействие регенерации и переводов, деплой-дисциплина, проверки перед пушем, дисциплина коммитов)

### Изменено
- **Версия из единого источника**: метаданные `/` читают версию из `package.json` (импорт на этапе сборки) вместо захардкоженного литерала; repo_audit проверяет package.json = CITATION.cff и согласованность дат релиза
- **Укрепление cron-батчей**: оффсеты/лимиты вынесены в экспортируемый `CRON_BATCH_CONFIG`; runtime-guard громко логирует расхождение числа источников; новый набор тестов `cron-batching` (4 инварианта: полное покрытие, непрерывность оффсетов, нумерация батчей, бюджет подзапросов); repo_audit проверяет совпадение кронов wrangler с ключами конфига
