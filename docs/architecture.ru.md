## 1. Обзор

Human–AI Monitor построен на **децентрализованной инфраструктуре Cloudflare** — глобальной сети edge-серверов, обеспечивающей:

- **Нулевой холодный старт** — Workers запускаются мгновенно.
- **Глобальное распределение** — код исполняется рядом с пользователем.
- **Бесплатный тариф** — до 100 000 запросов/день для Workers.
- **Отказоустойчивость** — нет единой точки отказа.

**Стоимость на старте:** $0.

## 2. Компоненты

### 2.1. Cloudflare Workers — «мозг» системы

**Роль:** Оркестрация сбора данных, классификации и публичного API.

**Единый Worker с двумя обработчиками:**

1. **Обработчик `fetch`** — публичный API:
   - `GET /` — метаданные проекта.
   - `GET /health` — проверка состояния.
   - `GET /gap` — текущий Gap Index.
   - `GET /protocols` — список еженедельных протоколов.
   - `GET /protocols/{week}` — метаданные одного протокола.
   - `GET /protocols/{week}/content` — содержимое в Markdown.
   - `GET /axes/{axis}` — сигналы по конкретной оси.
   - `GET /classify?text=...&kind=ai|human` — классификация произвольного текста.
   - `GET /collect?limit=N&max=M` — ручной сбор RSS.
   - `GET /generate?week=YYYY-MM-DD` — ручная генерация протокола.

2. **Обработчик `scheduled`** — Cron Trigger:
   - Запускается 5 раз в сутки батчами (13:00, 13:15, 13:30, 13:45, 23:00 UTC).
   - Каждый батч собирает свежие новости из 8–9 источников.
   - Классифицирует каждый элемент через Workers AI.
   - Сохраняет в D1.
   - Пятница 13:45 UTC: генерирует промежуточный протокол за текущую неделю.
   - Понедельник 13:45 UTC: генерирует итоговый протокол за предыдущую неделю.

**Технологии:** TypeScript, Wrangler CLI.

---

### 2.2. Cloudflare D1 — база данных

**Роль:** Хранение структурированных данных.

**Тип:** Serverless SQL (SQLite).

**Бесплатный тариф:**
- 5 ГБ хранилища.
- 5 млн чтений/день.
- 100 тыс. записей/день.

**Таблицы:**
- `items` — классифицированные сигналы (hash, title, url, axes JSON, relevance, shift, direction, reasoning).
- `protocols` — метаданные еженедельных протоколов + содержимое в Markdown.
- `gap_history` — динамика Gap Index.
- `index_history` — значения 13 осей (12+1) во времени.

**Binding:** `DB` (в `wrangler.jsonc`).

### 2.3. Cloudflare Workers AI — классификатор

**Роль:** Классификация сигналов по 13 осям (12+1).

**Модель:** `@cf/qwen/qwen3-30b-a3b-fp8` (open-weight, архитектура MoE).

**Почему Workers AI:**
- **Независимость** — open-weight модель, без внешних провайдеров.
- **Бесплатный тариф** — 10 000 нейронов/день.
- **Глобальный edge** — работает на 300+ локациях Cloudflare.
- **Без холодного старта** — мгновенный инференс.

**Binding:** `AI` (в `wrangler.jsonc`).

**Стоимость:** ~15 нейронов на классификацию (~660 классификаций/день бесплатно).

---

### 2.4. Cloudflare Cron Trigger — планировщик

**Роль:** Ежедневная автоматизация с батчевой обработкой.

**Расписание:** 5 батчей в сутки (UTC):
- `0 13 * * *` — батч 1 (источники 0-7)
- `15 13 * * *` — батч 2 (источники 8-15)
- `30 13 * * *` — батч 3 (источники 16-23)
- `45 13 * * *` — батч 4 (источники 24-31) + генерация протокола
- `0 23 * * *` — батч 5 (источники 32-40)

**Генерация протокола:**
- Пятница 13:45 UTC: промежуточный протокол за текущую неделю
- Понедельник 13:45 UTC: итоговый протокол за предыдущую неделю

**Что делает:**
1. Собирает свежие RSS-элементы.
2. Классифицирует через Workers AI.
3. Сохраняет в D1.
4. Генерирует Markdown-протокол за прошедшую неделю.
5. Запускает `sync-protocols.yml` и `translate-protocols.yml` через GitHub API (только пн/пт).

## 4. Безопасность

### 4.1. Секреты

Хранятся в **Cloudflare Secrets** (не в коде):
- `CLOUDFLARE_API_TOKEN` — для деплоя (локальный `.env`).
- `CLOUDFLARE_ACCOUNT_ID` — идентификатор аккаунта (локальный `.env`).

**Локально:** `.env` — **не коммитится** (в `.gitignore`).

**В Git:** только `.env.example` — шаблон без реальных значений.

### 4.2. Верификация

- **D1:** Wrangler проверяет токен и права.
- **API:** валидация параметров (длина text <= 1000 символов).
- **Без внешних AI-провайдеров:** весь инференс выполняется на open-weight моделях Cloudflare.

### 4.3. Приватность

- **Workers AI** — данные не используются для обучения моделей.
- **D1** — только структурированные публичные данные.
- **Без сторонней аналитики.**

## 6. Синхронизация протоколов

### 6.1. Генерация vs Видимость

Протоколы генерируются в базу D1, но **не становятся мгновенно видимыми** в репозитории. Синхронизацию выполняет workflow GitHub Actions `.github/workflows/sync-protocols.yml`.

### 6.2. Расписание

Протоколы генерируются Cloudflare Worker'ом в 13:45 UTC по пн/пт. Сразу
после генерации Worker параллельно запускает два workflow GitHub Actions
через API GitHub (`workflow_dispatch`):

| Workflow | Триггер | Назначение | Видимость |
|----------|---------|------------|-----------|
| `sync-protocols.yml` | Dispatch из Worker (пн/пт ~13:53 UTC) | Выкладывает EN/RU/ZH файлы в git | ~5–10 мин после генерации |
| `translate-protocols.yml` | Dispatch из Worker (пн/пт ~13:53 UTC) | Перегенерирует RU/ZH в D1 | Следующий цикл sync |

> **Историческая справка:** у обоих workflow остался триггер `schedule:`,
> но запуски по расписанию GitHub ненадёжны (задержки до 4+ часов,
> пропуски). Dispatch из Worker — основной и надёжный путь.

### 6.3. Задержка перевода

Английский — основной язык. Переводы RU/ZH перегенерируются асинхронно
workflow'ом `translate-protocols.yml`, параллельно с sync. Следствие:

- **EN-файлы** появляются в git через ~5–10 минут после генерации.
- **RU/ZH-файлы** могут отставать на один цикл sync (до ~3–4 дней):
  `sync` выкладывает те переводы, которые уже лежат в D1 на момент
  запуска, а `translate` обновляет D1 параллельно.

Это осознанный компромисс: перевод не на критическом пути, что позволяет
не превышать лимиты Cloudflare Free (subrequests, CPU time) на Worker'е,
который генерирует протоколы.

### 6.4. Детали workflow

`sync-protocols.yml`:
1. Забирает последние 2 протокола из D1 API (`/export-weekly?weeks=2`).
2. Записывает в `data/protocols/` в репозитории collector.
3. Архивирует все протоколы в репозиторий `human-ai-monitor-archive`.
4. Коммитит изменения в оба репозитория.

`translate-protocols.yml`:
1. Определяет последнюю неделю через `/protocols`.
2. Вызывает `GET /translate/{week}` (Bearer-токен), перегенерируя RU/ZH в D1.
3. Проверяет переводы через `/protocols/{week}/content/ru` и `/zh`.

Оба workflow запускаются Worker'ом параллельно. `sync` **не** вызывает
`translate`.

### 6.5. Синхронизация в чрезвычайных обстоятельствах

В нормальном режиме оба workflow запускаются автоматически Worker'ом
после генерации протокола. Ручной запуск нужен только в чрезвычайных
обстоятельствах: если автоматический dispatch не сработал или требуется
повторный запуск после частичного сбоя.

```bash
gh workflow run sync-protocols.yml
gh workflow run translate-protocols.yml
```

Эти команды — не часть штатной работы.


## 7. Масштабирование

### 7.1. По нагрузке

| Ресурс | Бесплатный тариф | При превышении |
|--------|------------------|----------------|
| Workers | 100 тыс. запросов/день | $5/месяц за 10 млн |
| D1 | 5 ГБ, 5 млн чтений/день | $0.75/ГБ |
| Workers AI | 10 тыс. нейронов/день | $0.011 за 1 тыс. нейронов |

На старте — всё укладывается в бесплатный тариф.

### 7.2. По географии

У Cloudflare 300+ edge-локаций.

Worker запускается ближе к пользователю.

У D1 есть региональные реплики.

### 7.3. По источникам

Добавление источника — одна строка в массиве SOURCES.

Масштабирование сбора — параллельные fetch-вызовы.

Масштабирование классификации — Workers AI автоматически справляется со всплесками.

## 9. Ограничения

- **Нет rate limiting.** Привязка rate limiting в Cloudflare экспериментальная и недоступна на бесплатном тарифе. Митигация: валидация параметров (text <= 1000 символов).

- **Только RSS-сбор.** Парсинг HTML пока не реализован. Некоторые источники без RSS недоступны.

- **D1 в одном регионе.** Сейчас EEUR. При росте — реплики.

- **Нет автоматических бэкапов.** Планируется: еженедельный экспорт D1 в R2.

- **Монолитный src/index.ts.** Рефакторинг на модули — в дорожной карте.
