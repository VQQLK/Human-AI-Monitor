## 1. Проект в одном абзаце

Мы строим **открытую систему мониторинга**, которая одновременно отслеживает развитие искусственного интеллекта (6 осей) и состояние Человечества (6 осей), а также мета-слой геополитики, вычисляет **Gap Index** — количественную меру расхождения между ними — и публикует еженедельные протоколы. Это не журналистика и не прогнозирование. Это **попытка операционализировать вопрос, который оставался риторическим**: наступает ли сингулярность, и что при этом происходит с человечеством.

По состоянию на 25 сентября 2026 года система прошла свой **первый полностью автономный дневной цикл** — 4 batch'а собрали 33 item'а из 17 источников, классификатор их обработал, и interim-протокол для текущей недели был сгенерирован без участия Человека.

## 2. Формальная структура

### 2.1. Оси ИИ (RSI)

| Символ | Что измеряется | Порог пересмотра |
|--------|----------------|------------------|
| SMD | Глубина самомодификации (L0–L4) | Воспроизводимый L4 в 2+ независимых системах |
| ITQ | Траектория улучшения (наклон, ускорение) | Переход в Transfer Set + ускорение > 0 |
| AGG | Автономная генерация целей | Экспертная значимость без внешнего задания |
| Cycle Velocity | Скорость цикла (время удвоения) | <2 месяцев + completion rate >50% |
| Verification | Иерархия верификации | False positive rate <5% без надзора |
| Hexad | Обнаружение фазового перехода (MMD) | Устойчивое превышение в 2+ системах |

### 2.1b. Геополитическая ось (мета-слой)

| Символ | Что измеряется | Порог пересмотра |
|--------|----------------|------------------|
| Геополитика | Управление ИИ, государственная политика | Крупный договор / экспортный контроль / национальная стратегия |

> **Методологическая симметрия:** |A| = 6 = |H|. Ось `geopolitics` — это **мета-слой**: измеряется и публикуется, но **НЕ входит** ни в AI_score, ни в Human_score (задокументировано в `docs/methodology.md`).

| Символ | Что измеряется | Порог тревоги |
|--------|----------------|---------------|

### 2.3. Байесовский уровень оси

Уровень каждой оси — латентная случайная величина на [0, 1] с апостериорным бета-распределением. Для оси a с множеством сигналов S_a = {s₁, …, s_n}:

    ℓ(a) | S_a ~ Beta( α₀ + Σ_{s ∈ S_a} v_s⁺ ,  β₀ + Σ_{s ∈ S_a} v_s⁻ )

где:
- α₀ = β₀ = 1/2 — неинформативное **априорное распределение Джеффрис**,
- v_s = r_s · π(σ_s, d_s) — голос сигнала,
- v_s⁺ = max(0, v_s),  v_s⁻ = max(0, −v_s).

**Таблица голосов** π(σ, d) ∈ [−1, 1]:

| π | up | stable | down | uncertain |
|---|---|---|---|---|
| **yes** | +1.0 | +0.5 | −1.0 | +0.5 |
| **no** | +0.3 | 0.0 | −0.3 | 0.0 |
| **uncertain** | 0.0 | 0.0 | 0.0 | 0.0 |

Точечная оценка:  ℓ̂(a) = (α₀ + Σv_s⁺) / (α₀ + β₀ + Σv_s⁺ + Σv_s⁻).

**Fallback.** При |S_a| = 0 апостериорное = априорному = Beta(0.5, 0.5), среднее 0.5, широкий кредибельный интервал (ранее — ложный ноль).

Полное байесовское изложение: [`docs/bayesian_framework.ru.md`](bayesian_framework.ru.md) §3.2.

### 2.4. Агрегация

AI-score и Human-score — простые арифметические средние по своим категориям:

    AI_score    = (1/|A|) · Σ_{a∈A} ℓ(a)  = (1/6) · Σ_{a∈A} ℓ(a)
    Human_score = (1/|H|) · Σ_{a∈H} ℓ(a)  = (1/6) · Σ_{a∈H} ℓ(a)

**Свойство нормализации:** обе метрики лежат в [0, 1] как средние значений из [0,1].

**Распределение Gap.** Gap строится методом Монте-Карло (M = 10 000 выборок):

    ℓ^(k)(aᵢ) ~ Beta(αᵢ, βᵢ),  ℓ^(k)(hⱼ) ~ Beta(αⱼ, βⱼ)   для k = 1..M
    Gap^(k) = AI^(k) − Human^(k)

Точечная оценка: Ĝap = mean({Gap^(k)}).  95% кредибельный интервал: [q₀.₀₂₅, q₀.₉₇₅].

### 2.5. Gap Index

    Gap = AI_score − Human_score

**Область значений:** Gap ∈ [−1, 1] (разность двух значений из [0,1]).

**Интерпретация** (кусочно-постоянная функция с порогами ±0.1 и ±0.3):

    Gap < −0.3          → Humanity significantly ahead
    −0.3 ≤ Gap < −0.1   → Humanity ahead
    −0.1 ≤ Gap ≤ 0.1    → Symmetric development
    0.1 < Gap ≤ 0.3     → AI ahead
    Gap > 0.3           → AI significantly ahead

**Нейтральная зона** [−0.1, 0.1] шириной 0.2 соответствует статистическому шуму при малых выборках (аналог «мёртвой зоны»).

Интерпретация **устойчива**, когда 95% кредибельный интервал Gap целиком лежит внутри одной строки, и **неустойчива**, когда интервал пересекает порог.

### 2.6. Классификатор (LLM-интерфейс)

Классификатор — это модель f: T* → Y*, применяемая к батчу элементов. Для одного элемента T — пространство текстов (title + summary, ≤800 символов), а выходное пространство:

    Y = {(A, r, σ, d, ρ)}

где:
- A ⊆ (AI_axes ∪ Human_axes), 1 ≤ |A| ≤ 3 (sparse),
- r ∈ [0, 1] — relevance score,
- σ ∈ {yes, no, uncertain} — shift flag,
- d ∈ {up, down, stable, uncertain} — direction,
- ρ ∈ T — reasoning (1–2 sentences).

**Критическое правило:** σ = yes допускается только при эмпирически подтверждённом threshold shift (правило 3 в `src/config/prompts.ts`).

### 2.7. Статистические свойства

- **Hash-check перед classify:** SHA-256 от URL/title → DB lookup → classify только новых. Эмпирическая экономия: ~90% LLM-вызовов.
- **Batch-обработка:** 5 батчей в сутки × ~8 источников × ~2-3 item/источник ≈ 80-120 классификаций/день.
- **Стандартная ошибка Gap.** Каждый сигнал вносит голос v_s = r_s · π(σ_s, d_s) ∈ [−1, 1] с дисперсией σ_v². При допущении однородности (равные размеры осей n_i = n/6, равные дисперсии сигналов):
    SE(Gap) = σ_v · √(2/n),   ширина CI₉₅ ≈ 3.92 · σ_v · √(2/n)  (для n ≥ 30).
  Вывод: Var(AI_score) = (1/36) Σ_i Var(ℓ(a_i)) = (1/36) · 6 · σ_v²/(n/6) = σ_v²/n. Аналогично для Human_score. При независимости Var(Gap) = 2 σ_v²/n, откуда SE(Gap) = σ_v · √(2/n).
  При консервативной границе σ_v ≤ 0.5 (для сигналов из [0, 1]), SE(Gap) ≤ √(1/(2n)) ≈ 0.707 / √n. Следствия:
    - n = 10:  SE(Gap) ≤ 0.22  (превышает полуширину нейтральной зоны 0.1 — интерпретация ненадёжна)
    - n = 50:  SE(Gap) ≤ 0.10  (на границе)
    - n = 170: SE(Gap) ≤ 0.054 (приемлемо; согласуется с текущей неделей)

## 3. Почему это интересно математикам

### 3.1. Формализация неформализуемого

Сингулярность до сих пор определялась **литературно** (Виндж, Гуд, Альтман). Мы предлагаем **измеримую структуру**: 6 осей ИИ + 6 осей человечества + 1 мета-ось (геополитика) с явными порогами, каждый из которых **фальсифицируем**.

Это попытка превратить **спекуляцию в гипотезу**, а гипотезу — в **наблюдаемую величину**.

### 3.2. Симметрия ИИ ↔ Человек

13 осей образуют **почти-симметричную структуру**: 7 параметров, описывающих **искусственное**, 6 — **человеческое**. Асимметрия (`geopolitics` как мета-слой) — сознательный выбор дизайна. Гипотеза симметрии сохраняется: **развитие ИИ и развитие человечества связаны**, и gap между ними — ключевая переменная.

### 3.3. Открытые математические проблемы

**Проблема 1. Критерий настоящего RSI.**

Когда самомодификация системы — это **устойчивое улучшение**, а когда — **насыщение**? Связано с теорией вычислимости (теорема Клинни о рекурсии, проблема остановки) и теорией информации (сложность Колмогорова).

**Формализация:** пусть S — самосовершенствующаяся система, S_t — её состояние в момент t. RSI — это процесс S_{t+1} = f(S_t), где f — сама система (рефлексивность). Устойчивость означает строгое монотонное улучшение с положительной нижней границей шага:

    ∃ ε > 0 : ∀t, Capability(S_{t+1}) − Capability(S_t) ≥ ε.

Это требует неограниченности Capability. Если Capability ограничена (например, на [0, 1]), строгое монотонное улучшение всё ещё возможно, но шаг должен стремиться к нулю, и «устойчивый рост» становится плохо определён. Вопрос: при каких условиях на f выполняется неограниченный случай?

**Проблема 2. Обнаружение фазового перехода.**

MMD-детектор (Hexad) — эвристика. Нужна строгая теория: **как отличить фазовый переход от шума** в самосовершенствующейся системе?

**Формализация:** пусть X_t — траектория SGD-итераций. Мы вычисляем MMD(X_t, N(0, I)) — расстояние до гауссовского суррогата. Вопрос: существует ли порог τ, при котором MMD > τ статистически значимо указывает на то, что X_t отклоняется от гауссовского суррогата?

**Проблема 3. Верификация без оракула.**

Иерархия верификации (формальные верификаторы → выполнение → LLM-судьи → самооценка) — это **частичный порядок**. Когда система может **замкнуть петлю без Человека**? Это вопрос о **вычислительной сложности самореференции**.

**Формализация:** пусть V = {v₁, ..., v_n} — иерархия верификаторов, где v_i < v_j означает «v_i менее надёжен, чем v_j». Система может замкнуть петлю без Человека, если существует v_i такой, что false_positive_rate(v_i) < 5% и v_i автономно применим. Вопрос: какова минимальная колмогоровская сложность K(v_i) такого верификатора?

**Проблема 4. Gap Index как динамическая система.**

G(t) — не скаляр, а траектория. Можно ли найти **инварианты**? Существуют ли **аттракторы**? Что происходит при G → ±1?

**Формализация:** пусть G(t) = F(A(t), H(t)), где A(t) — вектор уровней ИИ, H(t) — вектор уровней человечества. Вопрос: существуют ли сохраняющиеся величины вдоль траекторий G(t)? Существуют ли аттракторы внутри [−1, 1]?

## 4. Что делает проект уникальным

### 4.1. Открытость

- **Код:** MIT License, полностью на GitHub.
- **Данные:** все источники, промпты, миграции — открыты.

### 4.3. Двусторонность

Это **не монитор ИИ**. Это **монитор ИИ + Человечества**. Мы измеряем не только то, что делает ИИ, но **что происходит с нами**.

## 5. Масштаб идеи

### 5.1. Историческая аналогия

В 1957 году **Спутник** начал космическую гонку. В 1969 году **Apollo** высадил людей на Луну. В 2026 году **фронтирные AI-системы** выходят из песочниц и решают задачи, остававшиеся открытыми десятилетия.

**Но кто это наблюдает?** Корпорации публикуют релизы. Государства — декларации. Учёные — статьи. **Никто не публикует еженедельный отчёт о том, что происходит с человечеством.**

Мы публикуем.

### 5.2. Потенциальная трансформация

- **Сейчас:** еженедельный протокол в Markdown, 3 языка (EN/RU/ZH).
- **Через 6 месяцев:** Android-приложение с push-уведомлениями.
- **Через год:** публичный API для исследователей, журналистов, политиков.
- **Через 3 года:** глобальный стандарт мониторинга — открытый, воспроизводимый, независимый.
- **В итоге:** инструмент осознания — не просто данные, а **зеркало цивилизации**.

### 5.3. Философский смысл

Проект построен на одном вопросе: **«Что значит видеть собственный путь?»**

Мы не предсказываем будущее. Мы **наблюдаем настоящее** — ясно, систематически, открыто.

**Знание собственного пути не может быть привилегией.**

## 7. Расписание синхронизации протоколов

### 7.1. Генерация vs. видимость

Протоколы генерируются в **базу D1** и выкладываются в **git-репозиторий** (`data/protocols/`) самим Cloudflare Worker'ом. Синхронизация **не** является отдельной задачей по расписанию — сразу после генерации (пн/пт 13:45 UTC) Worker параллельно запускает два workflow GitHub Actions через API GitHub (`workflow_dispatch`):

- `sync-protocols.yml` — копирует файлы протоколов в git
- `translate-protocols.yml` — перегенерирует RU/ZH в D1

Такая схема устраняет зависимость от ненадёжного нативного планировщика GitHub.

### 7.2. Таблица задержек

| Тип протокола | Dispatch (D1) | Видимость (git) | Задержка |
|---------------|---------------|-----------------|----------|
| **Interim** (пятница) | пт ~13:53 UTC | пт ~14:00 UTC | ~5–10 мин |
| **Final** (понедельник) | пн ~13:53 UTC | пн ~14:00 UTC | ~5–10 мин |
| **Переводы RU/ZH** | пн/пт ~13:53 UTC | следующий цикл sync | до ~3–4 дней |

EN-файлы появляются в git в течение минут после генерации. RU/ZH-переводы перегенерируются асинхронно и могут отставать на один цикл sync.

### 7.3. Задержка перевода

Английский — основной язык. Переводы RU/ZH перегенерируются асинхронно workflow'ом `translate-protocols.yml`, который работает параллельно с `sync-protocols.yml`. Следствие:

- **EN-файлы** появляются в git через ~5–10 минут после генерации.
- **RU/ZH-файлы** могут отставать на один цикл sync: `sync` копирует те переводы, которые уже лежат в D1 на момент его запуска, а `translate` обновляет D1 параллельно.

Это осознанный компромисс — перевод не на критическом пути, что позволяет не превышать лимиты Cloudflare Free (subrequests, CPU time) на Worker'е, который генерирует протоколы.

### 7.4. Sync workflow

Определён в `.github/workflows/sync-protocols.yml` и запускается Cloudflare Worker'ом сразу после генерации протокола:

    on:
      schedule:
        - cron: "0 14 * * 1"   # Monday 14:00 UTC — legacy schedule
        - cron: "0 8 * * 6"    # Saturday 08:00 UTC — legacy schedule
      workflow_dispatch:        # Primary trigger (from Worker)

Workflow:
1. Забирает последние 2 протокола из D1 API (`/export-weekly?weeks=2`).
2. Пишет в `data/protocols/` в collector-репозитории.
3. Архивирует все протоколы в репозиторий `human-ai-monitor-archive`.
4. Коммитит изменения в оба репозитория.

Перевод выполняется отдельным workflow `translate-protocols.yml`, который тоже запускается Worker'ом параллельно. Он вызывает `GET /translate/{week}` с Bearer-токеном для перегенерации RU/ZH в D1, затем проверяет результат через `/protocols/{week}/content/ru` и `/zh`.

### 7.5. Синхронизация в чрезвычайных обстоятельствах

В нормальном режиме оба workflow запускаются автоматически Worker'ом. Ручной запуск нужен только в чрезвычайных обстоятельствах — если автоматический dispatch не сработал или требуется повторный запуск после частичного сбоя:

    gh workflow run sync-protocols.yml
    gh workflow run translate-protocols.yml

Эти команды — не часть штатной работы.

Полная документация: `docs/architecture.md` §6 «Синхронизация протоколов».

### Критические исправления v1.0.1 (25 сентября 2026)

В первоначальном релизе v1.0.0 были обнаружены и исправлены два критических бага:

**1. Русские ключи в gap-computation.ts (commit `13fa1c1`)**

Словари мультипликаторов `SHIFT_MULT` и `DIR_MULT` были объявлены с русскими ключами (`'да'`/`'нет'`/`'рост'`/`'падение'`), тогда как классификатор возвращал английские ключи (`yes`/`no`/`up`/`down`). Это приводило к тому, что lookup возвращал `undefined`, и fallback `?? 1` давал единичный множитель.

**Влияние:** Модель теряла чувствительность к сдвигам порогов и направленным трендам, фактически сводясь к средней relevance по оси.

**Исправление:** Все ключи мультипликаторов переведены на английский, восстановлена полная функциональность математической модели.

**2. Hang Miniflare после тестов (commit `5f5721d`)**

После прохождения всех 66 тестов Miniflare не закрывал ресурсы WebSocket, ZLIB потоки и FileHandle, что вызывало 10-секундный timeout hang (24s общее время вместо ~5s).

**Исправление:** Добавлен `test/global-teardown.ts` с 2-секундным grace period с последующим `process.exit(0)`. Уменьшен `teardownTimeout` с 10s до 3s. Отключены `remoteBindings` в тестах.

**Результат:** Тестовый набор теперь выполняется за **8 секунд** вместо 24 секунд.
