## 1. Введение

### 1.1 Проект

Human–AI Monitor — открытая система мониторинга, которая одновременно отслеживает развитие искусственного интеллекта и состояние Человечества и публикует еженедельные протоколы. Основной продукт — **Gap Index**, количественная мера расхождения между уровнем ИИ и уровнем Человечества.

### 1.2 Структура измерения

Система оперирует **13 осями**:

- **A = {a₁, …, a₆}** — шесть осей ИИ (RSI — Recursive Self-Improvement): `SMD` (Self-Modification Depth), `ITQ` (Improvement Trajectory Quality), `AGG` (Autonomous Goal Generation), `Cycle Velocity`, `Verification`, `Hexad`.
- **H = {h₁, …, h₆}** — шесть осей Человечества (HHI — Human Horizon Index): `H1 Agency`, `H2 Sovereignty`, `H3 Wellbeing`, `H4 Equity`, `H5 Meaning`, `H6 Democracy`.
- **G = {g}** — одна геополитическая мета-ось: измеряется и публикуется, но **не входит** ни в `AI_score`, ни в `Human_score`.

Формула структуры: `13 = 6 + 6 + 1`.

### 1.3 Гипотеза симметрии

Центральная гипотеза проекта: **развитие ИИ и развитие Человечества связаны**, и разрыв между ними — ключевая наблюдаемая переменная. Симметрия 6↔6 не случайна — она отражает гипотезу, что шесть RSI-осей и шесть HHI-осей описывают сопоставимые по значимости измерения.

**Математическое следствие.** Если гипотеза симметрии принимается как постулат, функция агрегации осей внутри каждой группы должна быть **инвариантна относительно перестановки осей**. Иначе симметрия нарушается на уровне формулы, а не на уровне теории. Это ограничивает класс допустимых агрегаторов.

### 1.4 Gap Index

Gap Index `G(t)`:

```
G(t) = AI_score(t) − Human_score(t)
```

где `AI_score` — агрегированная оценка уровня ИИ, `Human_score` — агрегированная оценка уровня Человечества.

### 1.5 Источник данных

Еженедельный сбор из ~40 RSS-источников. Каждый элемент классифицируется языковой моделью (Qwen 3, `@cf/qwen/qwen3-30b-a3b-fp8`) и получает:

- `r_s ∈ [0, 1]` — релевантность (уверенность классификатора),
- `σ_s ∈ {yes, no, uncertain}` — флаг порогового сдвига,
- `d_s ∈ {up, down, stable, uncertain}` — направление тренда,
- `A_s ⊆ (A ∪ H ∪ G)`, `1 ≤ |A_s| ≤ 3` — множество осей, к которым отнесён сигнал.

За неделю накапливается `|S| ≈ 100–200` сигналов, распределённых по осям. Множество сигналов, отнесённых к оси `a`, обозначается `S_a`.

## 2. Текущая методология (v1.0.1)

Это — действующая версия, реализованная в коде `src/services/gap-computation.ts` и частично отражённая в `docs/methodology.md`.

### 2.1 Уровень оси

Уровень оси вычисляется мультипликативной формулой:

```
ℓ(a) = clamp_[0,1] ( (1/|S_a|) · Σ_{s ∈ S_a} r_s · M_shift(σ_s) · M_dir(d_s) )
```

где `clamp_[0,1](x) = max(0, min(1, x))` — проекция на отрезок.

**Мультипликатор сдвига** `M_shift`:

| `σ_s` | `M_shift(σ_s)` |
|---|---|
| yes | 1.5 |
| uncertain | 1.0 |
| no | 0.5 |

**Мультипликатор направления** `M_dir`:

| `d_s` | `M_dir(d_s)` |
|---|---|
| up | 1.2 |
| stable | 1.0 |
| uncertain | 1.0 |
| down | 0.8 |

При `|S_a| = 0` (нет сигналов) полагается `ℓ(a) = 0`.

### 2.2 Агрегация

В коде используется **простое арифметическое среднее** по каждой группе:

```
AI_score    = (1/6) · Σ_{i=1}^{6} ℓ(a_i)
Human_score = (1/6) · Σ_{j=1}^{6} ℓ(h_j)
```

Геополитическая ось `g`: вычисляется `ℓ(g)` и публикуется в `index_history`, но не входит ни в `AI_score`, ни в `Human_score`.

### 2.3 Альтернативная формулировка в methodology.md

Документ `docs/methodology.md` (раздел 3.1–3.2) содержит **другую формулу** — взвешенную сумму с фиксированными весами:

```
AI_score    = Σ_{i=1}^{6} w_i^AI · a_i,     Σ w_i^AI = 1
Human_score = Σ_{j=1}^{6} w_j^H  · h_j,     Σ w_j^H  = 1
```

**Веса AI-осей:**

| Ось | Вес |
|---|---|
| SMD | 0.20 |
| ITQ | 0.15 |
| AGG | 0.15 |
| Cycle Velocity | 0.20 |
| Verification | 0.20 |
| Hexad | 0.10 |

**Веса Human-осей:**

| Ось | Вес |
|---|---|
| H1 Agency | 0.20 |
| H2 Sovereignty | 0.15 |
| H3 Wellbeing | 0.20 |
| H4 Equity | 0.15 |
| H5 Meaning | 0.15 |
| H6 Democracy | 0.15 |

**Эта формула не реализована в коде.** Код использует простое среднее. Расхождение между документом и кодом до сих пор не зафиксировано в методологии.

### 2.4 Пороги интерпретации

| Диапазон `G` | Интерпретация |
|---|---|
| `G > 0.3` | ИИ значительно впереди |
| `0.1 < G ≤ 0.3` | ИИ впереди |
| `−0.1 ≤ G ≤ 0.1` | Симметричное развитие (норма) |
| `−0.3 ≤ G < −0.1` | Человечество впереди |
| `G < −0.3` | Человечество значительно впереди |

(В `methodology.md` зафиксированы симметричные пороги `±0.1` и `±0.2`; в коде — `±0.1` и `±0.3`. Ещё одно расхождение.)

### 2.5 Ограничения текущего подхода

**Ограничение 1. Произвольные параметры.**
Значения `M_shift ∈ {1.5, 1.0, 0.5}` и `M_dir ∈ {1.2, 1.0, 0.8}` не выведены ни из теории, ни из калибровки на labeled data. Это набор экспертных чисел без документированного протокола их получения. Как следствие — метрика не воспроизводима: читатель не может проверить, почему именно 1.5, а не 1.3.

**Ограничение 2. Несогласованность документа и кода.**
Код использует простое среднее; `methodology.md` §3.1–3.2 описывает взвешенную формулу. Два документа говорят о разных метриках, обе заявлены как актуальные.

**Ограничение 3. Мультипликативность на ограниченном отрезке.**
При `r_s = 1`, `σ_s = yes`, `d_s = up` получаем `1 · 1.5 · 1.2 = 1.8`. До применения `clamp` значение выходит за `[0, 1]` в 1.8 раза. Операция `clamp` становится доминирующей над агрегацией: нелинейность у границ съедает разницу между сигналами с высокой релевантностью.

**Ограничение 4. Асимметрия силы эффектов.**
Диапазон shift: `1.5 / 0.5 = 3×`. Диапазон direction: `1.2 / 0.8 = 1.5×`. Почему shift влияет вдвое сильнее direction — не обосновано.

**Ограничение 5. Точечная оценка без неопределённости.**
Формула возвращает одно число без интервала. При `|S_a| < 10` (как на неделе 14–20 сентября 2026: 6 items в протоколе) стандартная ошибка среднего превышает ширину нейтральной зоны `[−0.1, 0.1]`, и интерпретация становится неотличимой от шума. Метрика этого не отражает.

**Ограничение 6. Несогласованность с гипотезой симметрии.**
Гипотеза §1.3 требует инвариантности относительно перестановки осей внутри группы. Формула взвешенной суммы (§2.3) её нарушает: веса `0.20` и `0.15` фиксируют предпочтения между осями без обоснования. Простое среднее (§2.2) инвариантно, но применяется в коде без явной теоретической мотивации.

## 3. Байесовская методология (v2.0)

Предлагаемая модель заменяет эвристику на вероятностную постановку. Уровень оси становится латентной величиной с апостериорным распределением; Gap становится распределением, а не скаляром.

### 3.1 Постановка задачи

Для каждой оси `a ∈ A ∪ H ∪ G` требуется:

1. Оценить уровень `ℓ(a) ∈ [0, 1]` с полным распределением неопределённости.
2. Построить `AI_score`, `Human_score`, `Gap` как распределения.
3. Обеспечить естественное обновление при поступлении новых сигналов.

### 3.2 Байесовская модель для одной оси

**Априорное распределение.** Уровень оси `ℓ(a)` — латентная величина на `[0, 1]`. Используем сопряжённое априорное распределение:

```
ℓ(a) ~ Beta(α₀, β₀)
```

Выбор `α₀ = β₀ = 1/2` — **априор Джеффриса** (Jeffreys 1946), неинформативный и инвариантный относительно репараметризации. Априорное среднее `E[ℓ] = 0.5` — нейтральная оценка при отсутствии данных.

**Голос сигнала.** Каждый сигнал `s ∈ S_a` даёт «голос» `v_s ∈ [−1, 1]`:

```
v_s = r_s · π(σ_s, d_s)
```

где `π` — детерминированная таблица направленности (§3.4).

Разделяем голос на положительную и отрицательную части:

```
v_s⁺ = max(0, v_s)
v_s⁻ = max(0, −v_s)
```

**Апостериорное распределение.** Благодаря сопряжённости Beta-правдоподобия с Beta-априором:

```
ℓ(a) | S_a ~ Beta( α₀ + Σ_{s ∈ S_a} v_s⁺ ,  β₀ + Σ_{s ∈ S_a} v_s⁻ )
```

**Точечная оценка:**

```
ℓ̂(a) = ( α₀ + Σ v_s⁺ ) / ( α₀ + β₀ + Σ v_s⁺ + Σ v_s⁻ )
```

**Дисперсия:**

```
Var[ℓ(a) | S_a] = α·β / ( (α+β)² · (α+β+1) )
```

где `α = α₀ + Σ v_s⁺`, `β = β₀ + Σ v_s⁻`.

**95% кредибельный интервал** `[q₀.₀₂₅, q₀.₉₇₅]` — квантили Beta-распределения.

### 3.3 Агрегация и Gap Index

**AI_score и Human_score.** По гипотезе симметрии (§1.3) обе группы равнозначны, поэтому агрегация — **простое среднее**:

```
AI_score    = (1/6) · Σ_{i=1}^{6} ℓ(a_i)
Human_score = (1/6) · Σ_{j=1}^{6} ℓ(h_j)
```

Это единственная агрегация, инвариантная относительно перестановки осей.

**Важное свойство:** если `ℓ(aᵢ) ~ Beta(αᵢ, βᵢ)` независимы, то `AI_score` **не распределён как Beta** — это сумма бета-распределённых величин, для которой нет замкнутой плотности. Это не дефект модели, а её честность: агрегация действительно меняет форму распределения.

**Gap:**

```
Gap = AI_score − Human_score
```

**Построение распределения Gap методом Монте-Карло** (Robert & Casella 2004, гл. 3):

1. Сэмплируем `M = 10 000` раз:
   - `ℓ^(k)(aᵢ) ~ Beta(αᵢ, βᵢ)` для `i = 1..6`
   - `ℓ^(k)(hⱼ) ~ Beta(αⱼ, βⱼ)` для `j = 1..6`
2. Считаем `Gap^(k) = AI^(k) − Human^(k)`.
3. Оценки:
   - `Ĝap = mean(Gap^(k))`
   - `CI₉₅ = [q₀.₀₂₅, q₀.₉₇₅]({Gap^(k)})`
   - `Var(Gap) = var({Gap^(k)})`

Выбор `M = 10 000` даёт погрешность Монте-Карло ~`1/√M ≈ 0.01` для среднего и ~0.005 для квантилей — ниже значимой точности публикации (2 знака).

### 3.4 Таблица направленности π

Таблица `π(σ, d) ∈ [−1, 1]`:

| π | up | stable | down | uncertain |
|---|---|---|---|---|
| **yes** | +1.0 | +0.5 | −1.0 | +0.5 |
| **no** | +0.3 | 0.0 | −0.3 | 0.0 |
| **uncertain** | 0.0 | 0.0 | 0.0 | 0.0 |

**Обоснование значений:**

- `(yes, up) = +1.0` — полное свидетельство роста: сдвиг подтверждён и направление положительное.
- `(yes, down) = −1.0` — полное свидетельство падения: сдвиг подтверждён и направление отрицательное.
- `(yes, stable) = +0.5` — сдвиг есть, направление не определено, половина в пользу роста (консервативно).
- `(no, up/down) = ±0.3` — сдвига нет, но тренд есть, слабое свидетельство (30% от полного).
- `(no, stable) = 0.0` — ничего не происходит.
- `(uncertain, *) = 0.0` — при неопределённости сигнал не голосует (принцип «не навреди»).

Шкала `{1.0, 0.5, 0.3, 0.0}` — экспертная, открытая для калибровки. В отличие от мультипликаторов v1, она:

- **аддитивна** (не масштабирует `r_s`, а добавляет голос),
- **симметрична** (`π(yes, up) = −π(yes, down)`),
- **ограничена** (не выходит за `[−1, 1]`),
- **интерпретируема** как доля полного свидетельства.

### 3.5 Свойства байесовской модели

**Свойство 1. Корректная квантификация неопределённости.**
Кредибельный интервал `CI₉₅` построен из апостериорного распределения (Rubin 1984). При малых выборках интервал расширяется автоматически, делая интерпретацию честной.

**Свойство 2. Согласованность с гипотезой симметрии.**
При `αᵢ = αⱼ` и одинаковом числе сигналов распределения уровней AI- и Human-осей симметричны относительно перестановки. Ни одна ось не выделена.

**Свойство 3. Естественное обновление.**
Апостериор текущей недели становится априором следующей (sequential Bayesian updating). Не требуется пересчёт всей истории.

**Свойство 4. Устойчивость к малым выборкам.**
При `|S_a| = 0` апостериор = априор = `Beta(0.5, 0.5)`, среднее 0.5, широкий интервал. Корректное поведение вместо ложного нуля.

**Свойство 5. Фальсифицируемость.**
Gap как распределение допускает статистическую проверку гипотезы «Gap значимо отличается от нуля»: `P(Gap > 0 | data) > 0.95` — байесовский аналог одностороннего теста (Kruschke 2013).

### 3.6 Ограничения байесовской модели

**Ограничение 1. Независимость сигналов.** Модель предполагает независимость сигналов внутри оси. В реальности один источник может давать коррелированные сигналы (серия новостей об одном событии), что завышает уверенность. Обходной путь — random effects на источник (в v2.1).

**Ограничение 2. Экспертный характер π.** Таблица `π` — экспертная шкала. Формальная калибровка требует labeled data, которой пока нет. v2.0 публикует чувствительность к изменению `π`.

**Ограничение 3. Стационарность.** Модель не учитывает тренды на длинных горизонтах: апостериор одной недели не «помнит» предыдущую. Для долгосрочного анализа потребуется state-space модель (Kalman filter / hierarchical Bayes).

### 3.7 Процедура инференса

**Вход:** сигналы за неделю, сгруппированные по осям.

**Алгоритм:**

```
для каждой оси a ∈ A ∪ H ∪ G:
    α ← 0.5
    β ← 0.5
    для каждого сигнала s ∈ S_a:
        v ← r_s · π(σ_s, d_s)
        если v > 0: α ← α + v
        иначе:     β ← β + (−v)
    posterior[a] ← Beta(α, β)

для каждого сэмпла k = 1..10000:
    AI_k    ← (1/6) Σ_{i=1..6} Sample(posterior[a_i])
    Human_k ← (1/6) Σ_{j=1..6} Sample(posterior[h_j])
    Gap_k   ← AI_k − Human_k

Gap_mean ← mean({Gap_k})
Gap_CI95 ← [q₀.₀₂₅, q₀.₉₇₅]({Gap_k})
```

**Сложность:** `O(|S| + 12·M)`. На Cloudflare Workers с `M = 10 000` — порядка 50 мс.

**API-ответ `/gap` в байесовской версии:**

```json
{
  "week_start": "2026-09-21",
  "ai_score": 0.55,
  "ai_score_ci95": [0.51, 0.59],
  "human_score": 0.53,
  "human_score_ci95": [0.49, 0.57],
  "gap_mean": 0.02,
  "gap_ci95": [-0.05, 0.09],
  "gap_std": 0.04,
  "sample_size": 189,
  "statistically_significant": false,
  "interpretation": "Symmetric development"
}
```

Публикуется значение, неопределённость и признак значимости — три компонента научно корректной метрики.

### 3.8 Пороги интерпретации в байесовской модели

Пороги `±0.1` и `±0.3` сохраняются как **практическая шкала**, но с двумя дополнениями:

1. Если `CI₉₅` полностью лежит внутри одного интервала — интерпретация устойчива.
2. Если `CI₉₅` пересекает границу между интервалами — интерпретация помечается как неустойчивая.

Это дополнение не меняет шкалу, но делает её применение статистически корректным.

### 3.9 Соответствие принципам проекта

Байесовская модель соответствует пяти принципам, зафиксированным в `methodology.md` (раздел 5):

- **Прозрачность.** Все параметры модели (`α₀`, `β₀`, таблица `π`) публикуются; процедура Монте-Карло воспроизводима.
- **Воспроизводимость.** При одинаковых входных данных результат детерминирован с точностью до `1/√M` (при фиксированном seed — точно).
- **Фальсифицируемость.** Каждое утверждение о Gap имеет явный статистический смысл через `CI₉₅` и `P(Gap > 0 | data)`.
- **Независимость.** Модель опирается на open-weight LLM и открытые данные; вероятностный аппарат стандартен.
- **Бесплатность.** Монте-Карло на `M = 10 000` укладывается в бесплатный тариф Cloudflare Workers.

## 4. Сравнение подходов

| Критерий | Текущая v1.0.1 | Байесовская v2.0 |
|---|---|---|
| Уровень оси | Мультипликативная эвристика | Апостериорное Beta |
| Параметры | 4 числа без обоснования | 2 неинформативных априора |
| Агрегация | Простое среднее (код) или веса (документ) | Простое среднее |
| Gap | Скаляр | Распределение |
| Неопределённость | Скрыта | Явная (`CI₉₅`) |
| Малые выборки | Ложно уверенное число | Честно широкий интервал |
| Обновление | Полный пересчёт | Sequential (апостериор → априор) |
| Согласованность с §1.3 | Нарушена весами | Соблюдена |
| Фальсифицируемость | Слабая | Сильная |
| Артефакты clamp | Есть | Нет |

**Вывод.** Байесовская модель не «лучше» эвристики в смысле точности — обе дают точечную оценку. Байесовская **честнее**: она публикует неопределённость, а не скрывает её в параметрах, и согласована с гипотезой симметрии математически, а не декларативно.
